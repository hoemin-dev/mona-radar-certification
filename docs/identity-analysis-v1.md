## Normalization 영향

회사명 raw distinct는 17,444개다. 분석용으로 Unicode NFKC, `(주)`/`㈜`/`주식회사` 제거, 괄호·공백 제거, 소문자화를 적용하면 13,994개로 3,450개 감소한다. 표본 행 출현은 `(주)` 26,662건, `㈜` 6,068건, `주식회사` 13,372건이다.

이 감소는 동일 회사임을 증명하지 않는다. 법인표기 제거 후 동명이인 충돌, 개인사업자, 협동조합 표기, 회사명 변경을 구분할 사업자번호가 없다. 분석용 candidate generation에만 사용해야 한다.

제품명은 공백/줄바꿈/NBSP 정리 후 30,112 distinct와 변경 행 0건으로, 현재 parser가 이미 이 수준의 기계적 정리를 수행한다.

- 같은 type/no에 여러 기간: 3,026그룹.
- 같은 type/no/company에 여러 기간: 2,451그룹.
- 같은 type/no에 제품 변형: 1,888그룹.

이는 갱신, 공동 인증, 적용 제품 변경, 표기 변화, 원천 중복이 혼합된 패턴이다. 현재 snapshot만으로 renewal을 확정하지 않는다.

## Identity 등급

- A `(type,no)`: **UNSAFE** — 8,025 충돌 그룹, 유형별 의미 차이 큼.
- B `(type,no,company)`: **UNSAFE** — 7,205 충돌 그룹, 회사명도 안정 ID가 아님.
- C `(type,no,company,product)`: **PROVISIONAL** — entity candidate clustering에는 가장 유용하지만 6,361 충돌 그룹, 제품명 NULL 1,367건, lifecycle 변경 시 key가 깨짐. UNIQUE key로는 UNSAFE.
- D `(type,no,company,start_date)`: **UNSAFE** — 7,113 충돌 그룹이며 갱신 시 entity를 분리하고 시작일 NULL 777건을 포함한다.

## 추천 전략

내부 surrogate `certification_entity_id`를 사용하고, 목록 occurrence는 절대 병합하지 않는다. C 기반의 normalized fingerprint는 `identity_candidate_key`로만 저장하며 confidence와 rule version을 붙인다. 유형별 번호 특성과 향후 상세 식별값/사업자번호/반복 snapshot 증거가 확보된 뒤 entity 연결을 승인한다.

`source_row_no`는 run 내부 completeness/pagination 검증에만 사용하고 영구 ID로 승격하지 않는다.

## Company 연결

업체명은 전 행에 있지만 대표자·주소는 대량 NULL이고 사업자번호는 없다. 이름 normalization만으로 Company master에 직접 FK를 만들면 동명이인, 법인표기 변형, 사명 변경, 개인사업자를 오연결할 수 있다. 향후 연결은 후보 매칭 테이블과 evidence/confidence를 사용하며 Company DB를 source of truth로 유지해야 한다.
